# ---- the registration, before any measurement (the experiment ledger, verbatim) ----
H-SPLIT-TEXT (registered 2026-10-18, before any measurement)
Observation (code reading): pdf.js 5.4.149's TextLayer constructor calls setLayerDimensions(container, viewport), which
writes the container's width/height as `round(down, var(--total-scale-factor) * <W>px, var(--scale-round-x))` (CSS
round() is supported in Electron's Chromium). This app's CSS never defines --scale-round-x/-y (pdf_viewer.css does, on
.pdfViewer .page; the app does not load it), so the declarations are invalid at computed-value time and the layer's
width/height compute to auto. .vv-pdf-text is `position:absolute; inset:0`, so the layer then takes its SHEET's size.
On a whole page the sheet is the page: harmless. On a split page (second screen) the sheet is the slide HALF, and
offset-layer! moves only left/top: with the slide on the LEFT (x = 0, e.g. beamer-notes-right.pdf) the layer is the
half's width; with the slide on the RIGHT it is sheet + x·scale = the full page.
Hypothesis: in the slides layout of a slide-LEFT split deck, the engine's text layer is HALF the page wide, so every
root-level run (`left: L%`) sits at L % of the half instead of L % of the page — find highlights and selection boxes sit
at half their x.
Predictions (slides layout, the current page's .vv-pdf-text and one root-level run with a percent left):
  P1 split, slide left  : layer.width / sheet.width = 1 (± 0.01), and (run.left - layer.left) / (2·sheet.width) =
                          0.5 · L/100 (± 0.005) — the run sits at half its x.
  P2 control, whole page: layer.width / sheet.width = 1, and (run.left - layer.left) / sheet.width = L/100.
  P3 after the fix (the layer's size written in px after the TextLayer constructor, as pdf-region/place-text! does):
                          split, slide left: layer.width / sheet.width = 2 (± 0.01) and
                          (run.left - layer.left) / (2·sheet.width) = L/100 (± 0.005).
Refuted if P1 fails (the layer is the full page already): then nothing is to be fixed in the engine.
